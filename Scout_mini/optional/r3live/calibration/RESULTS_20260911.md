# Scout实测外参约束研究结果，2026-09-11

结论：工具已完成端侧部署、编译、算法测试和真实数据研究，但没有一套优化结果同时通过独立场景改善和稳定性验收。所有运行外参、导航参数、TF均未改；没有生成或启用新的accepted_calibration.yaml。应保留实测参数作为先验，不能因为求解收敛就替换。

## 1. 已核实的原点问题

用户确认安装位置量到雷达外壳/几何中心，不是内部IMU原点。现有rig.yaml把`xyz=[0.25,0,0.20]`、`rpy=[0,45,0]°`记为base_to_imu，相机安装为`xyz=[0.27,0,0.10]`、rpy零。两者数值与Scout旧配置一致，但雷达测量参考点与字段含义不一致。

旧程序还计入`T_imu_lidar`的平移`[-0.011,-0.02329,0.04412]m`，长度约5.11cm。研究对照两种解释：旧IMU解释；把实测中心近似当作雷达坐标原点，减去旧矩阵中额外计入的`R_camera_lidar*t_imu_lidar`。这不代表外壳几何中心等于厂家雷达原点，更不能据此认定实际误差就是5.11cm。相机工厂内部光学TF仍来自采集数据。

研究仅改变离线先验矩阵，不回写rig.yaml或改变已有采集点云。`T_camera_lidar`始终表示`p_camera_optical=T_camera_lidar*p_lidar`，平移单位米；相机光学轴为右、下、前。用于R³LIVE时另按`T_imu_camera=T_imu_lidar*inverse(T_camera_lidar)`转换，但本次没有执行部署外参。

## 3. 最终算法和测试边界

最终程序为prior_refine.py，实际运行目录`~/r3live_ws/calibration/runs/prior_robust_final_20260911/`。上游C++只提取真实平面交线和图像边缘，新优化器不使用旧VPnP方向残差。

固定几何样本，优化到可靠图像边缘的最近欧氏距离。数据Huber鲁棒化，20px之外保留常数惩罚，不删除样本、不继续让粗大误匹配拉动外参。像素尺度2px，各训练场景等权，总等效观测权重200；测量先验单独二次惩罚。旋转/平移尺度分别试0.5°/5mm、1°/10mm、2°/20mm，均为敏感性假设。数值收敛、拟合前后每场景至少30匹配、最终增量模长不触及约3倍假设尺度才作为候选；仍需独立验收。

提取器在ARM64/ROS Noetic上串行编译通过。算法测试包含斜线垂距审计、非零旋转与杆臂变换、带错误图像边缘的已知非零外参恢复、可靠匹配不足拒绝、投影丢失计入50px惩罚。此前实验中外循环反复切换局部直线不稳定，最终改为固定样本目标；相关旧研究目录仅保留追查，不代表最终可用结果。

最终端侧test_prior_refine.py四组测试通过（1.889秒）；两份上游补丁反向校验通过，refine --help和bash语法检查通过。研究结束私有master已退出，11311仍只有Livox、相机及rosout节点，没有新TF/底盘控制发布者。

## 4. 相同几何样本上的独立对照

validation_00固定684个真实交线样本，validation_03固定116个。基线FOV确定样本，候选移出视野按50px计入；表格为几何点到提取图像边缘的距离，不是外参物理误差。它与旧project的近似法向/深度边缘指标不同。

| 方案 | 网绳场景中位/P90（px） | 门角场景中位/P90（px） | 状态 |
|---|---:|---:|---|
| 实测中心近似雷达原点 | 2.44 / 8.33 | 8.26 / 16.85 | 研究基线，原点偏差未知 |
| 旧IMU原点解释 | 1.95 / 6.94 | 10.98 / 27.40 | 对照基线 |
| 第一次旧无约束求解 | 2.82 / 50.00 | 2.82 / 17.57 | 未接受 |
| 第二次旧无约束求解 | 2.80 / 50.00 | 7.05 / 25.66 | 未接受 |
| 新紧先验 | 3.61 / 16.16 | 2.33 / 8.29 | 触及约束，拒绝 |
| 新中先验 | 3.08 / 24.03 | 4.17 / 7.22 | 触及约束，拒绝 |
| 新宽先验 | 3.06 / 23.91 | 4.38 / 7.24 | 数值候选，未通过整体验收 |

宽先验修正相对研究基线约3.283°、2.520cm；紧/中先验的旋转修正约2.300°/3.253°，超过相应约3倍尺度，被拒绝。最终各档数值求解均收敛，拒绝不是编译或程序崩溃造成的。不能只挑门角某一列更好就接受，因为另一独立场景和投影覆盖仍变差。

固定中档先验逐一移除scene_00、scene_01、scene_02、validation_02后，四次结果都触及约束而被拒绝（旋转修正约2.463°、3.181°、3.962°、3.399°，平移约3.035、2.342、2.404、3.130cm）。这表明现有证据不支持在该测量尺度内得到可靠一致的修正；不等同于证明里程计、相机或雷达硬件有故障。

## 5. 当前建议与复现

不再为得到“通过”而放宽先验、降低验收门槛或重复盲目采集。下一步先按Mid-360机械坐标定义核实外壳测量点到雷达原点的偏移；在已有清晰门框/墙地交线图上核实少量三维交线与图像的真实对应，区分遮挡伪交线、错误对应与真实外参偏差。现有数据和对照图已经足够开展这一步，暂不要求重录。

复现完整研究（名字已存在，重跑需换名）：

```bash
~/r3live_ws/scout_calibrate.sh refine prior_robust_final_20260911 \
  --training scene_00 scene_01 scene_02 validation_02 \
  --validation validation_00 validation_03 \
  --mount-reference lidar-center-hypothesis \
  --compare-runs run_20260911_01 run_20260911_02
```

查看study.yaml的全部候选/训练留一/指标，comparison/下绿色图像边缘与红色真实交线，以及manifest.yaml的原点解释和数据来源。具体实现、参数和编译步骤见同目录README第8节及三大V5.1手册。
