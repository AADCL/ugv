## 1. 当前正式方案

V5.1 保留 Livox、FAST-LIO2、PCD/NDT、PGM、分类点云和高程文件，但导航接口仍是成熟的 ROS1 二维 costmap：

```text
静态路线：Livox -> FAST-LIO -> 贝叶斯静态 PCD
                            -> public_map.pcd（NDT 地图）
                            -> PMF 种子 + 连续地面/障碍重建 -> PGM + 高程/坡度

局部路线：FAST-LIO 当前帧 -> terrain_sensor -> Patchwork++ -> Terrain Guard
                                               -> 实时障碍/清除点 -> 局部 costmap

普通导航：NDT 给出 map->odom；PGM + 坡度层 -> GlobalPlanner -> TEB -> /cmd_vel

探索：局部障碍层的未膨胀观测 -> 轻量未知/空闲/障碍记忆图
      -> 全局 costmap -> explore_lite 独立分支选目标 -> GlobalPlanner/TEB
      -> /nav_cmd_vel -> 安全门 -> /wheeltec_driver/cmd_vel -> 探索底盘
      原静态 PCD 同时在内存积累 -> 正常结束保存 -> 人工 finalize_map.py
```

关键约束：

- 普通导航由 PGM 决定墙体、固定障碍和未知区域；坡度层只能给 PGM 已知格增加代价。探索用实时局部观测维护轻量记忆图，不在线拟合高程或叠加离线坡度代价。
- 高程地图提供全局坡度代价和可视化；局部障碍通过当前帧地面分割得到，不查询保存高程。
- 全局规划器是 `global_planner/GlobalPlanner`，局部规划器只使用 TEB；DWA 和旧 `TerrainGlobalPlanner` 不在正式入口中。
- 普通导航和探索均启动 Patchwork++ 与 Terrain Guard。手动建图默认只积累贝叶斯静态 PCD，在线地形分类仅为可选诊断。
- 本版本目标是平地、全局斜坡以及平地与坡道组合路段。楼梯语义和跨层地图不属于当前验收范围。

车体采用前、左、上坐标。实测 `base_link` 离地 `0.15 m`，雷达离地 `0.30 m`，因此雷达位于车体中心前 `0.10 m`、上 `0.15 m`，雷达朝车头方向下压 `20 deg`。Patchwork++ 的 `sensor_height` 必须填写雷达相对地面的绝对高度 `0.30 m`，不能误填为外参高度 `0.15 m`。两处配置必须表达同一个刚体关系：


## 6. 配置地图生成

### 6.1 唯一建图入口

打开 `wheeltec_system_bringup/launch/wheeltec_mapping.launch`。它必须在同一入口中启动：

1. Mid-360；
2. FAST-LIO2；
3. `wheeltec_pointcloud_mapper`；
4. TF 与 pose adapter；
5. 轮趣串口底盘；
6. 默认不启动在线地形分割；
7. 只有设置 `enable_online_terrain_diagnostics:=true` 时才启动 `cloud_adapter`、Patchwork++ 和 ground/nonground 累积器；
8. `terrain_guard` 始终仅按需诊断。

正式建图必须共用一套静态点判定，数据流如下：

```text
/cloud_registered
  -> wheeltec_pointcloud_mapper（半径滤波 + 唯一可逆贝叶斯静态判定）
     -> filtered_camera_init.pcd
        -> public_map.pcd（map 坐标，唯一静态权威）
           -> 大窗口 PMF 保守种子
           -> 局部平面验证与连续坡面生长
           -> 相对地面 0.04-1.50 m 障碍重分类
           -> PGM + 2.5D 地图
```

正式建图无需在线地形分割。需要回归 Patchwork++ 时，设置 `enable_online_terrain_diagnostics:=true`，此时 `terrain_input_topic` 默认仍必须是 `/wheeltec/static_scan`；只有诊断静态滤波时才临时改为 `/cloud_registered_body`。由于静态判定要求至少 12 次命中并跨越 2 秒，启动后的前约 `2 s` 没有稳定静态输出属于正常现象。

`wheeltec_pointcloud_mapper` 是唯一动态/静态权威；三维 DDA 自由射线可以把已确认体素降级，并使整代精细地图点失效。`finalize_map.py` 直接读取这份贝叶斯静态 PCD：大窗口 PMF 先给出稀疏且保守的地面种子，随后每个候选格必须通过二维支撑、局部平面残差和法向连续性检查，才能沿不超过 `25°` 的坡面生长。该设计既能恢复 PMF 单独处理时会丢失的长坡，也阻断旧算法沿窄墙/渐变链爬到顶棚。最终按相对高度 `0.04-1.50 m` 重提取同源静态障碍；不再累积第二份不可修改的标签地图，也不再做重复静态门控。PGM 和 2.5D 只读取最终的 `terrain_ground_map.pcd` 与 `terrain_obstacles_map.pcd`。导航阶段继续使用 `/cloud_registered_body` 的实时点云做局部障碍检测。

采集期间自动保存的是贝叶斯静态 PCD 和轨迹；正式分类 PCD、PGM、高程由正常退出后的 `finalize_map.py` 生成。只有显式启用旧在线诊断时才另有分类累积。用户不需要调用手动 finish 服务。

### 6.2 PGM 参数

打开：

```text
wheeltec_map_tools/config/wheeltec_raw.yaml
wheeltec_map_tools/config/wheeltec_nav.yaml
```

正式导航读取 `map_raw.yaml`，静态障碍不预膨胀；全局 costmap 使用 `0.15 m` 膨胀保持窄门拓扑连通，局部 costmap 使用 `0.22 m` 膨胀。`map.yaml` 兼容图也不预膨胀，防止保存地图和运行时对同一门框重复膨胀。

分类 PGM 以每格 ground 点的 20% 高度分位数作为地面。nonground 点只有在附近 `0.35 m` 内存在地面，且相对地面高 `0.04-1.50 m`、同格至少 2 点时才成为障碍。该规则用于保留低矮障碍，同时排除天花板和孤立单点噪声。

### 6.3 高程和坡度参数

打开 `wheeltec_2p5d_navigation/config/terrain_builder.yaml`：

```yaml
resolution: 0.10
ground_height_percentile: 0.20
max_fill_radius_cells: 4
min_fill_neighbors: 3
fit_radius_m: 0.30
smooth_height_delta_m: 0.12
preferred_slope_deg: 5.0
max_slope_deg: 25.0
max_slope_cost: 80
min_lethal_neighbors: 4
fuse_static_obstacles: false
```

每格保存一个地面高度；小孔洞只在有足够邻居时填充；局部平面给出坡度；5 度以内不增加坡度成本，5-25 度逐渐增加软代价，持续超过 25 度才成为致命坡度。2.5D 不再重复融合 nonground 静态障碍，PGM 是全局静态障碍的唯一权威。坡面补偿高度残差继续保存为诊断层，不直接判死，避免稀疏点和填洞边缘把平地大面积误判为障碍。

默认流程不再累积分类点云。静态资格由 pointcloud mapper 统一要求至少 `12` 次命中、跨 `2.0 s` 且命中率不低于 `60%`；已晋升体素只有在至少 `8` 次自由射线并持续 `0.75 s` 后才降级。PGM 投影每个 `0.05 m` 栅格至少需要 `2` 个有效障碍点，以降低单点噪声，同时保留低矮障碍。保存的 `base_link` 轨迹在转换时提供半径 `0.20 m` 的自由走廊，但不能覆盖任何障碍格。

### 6.4 探索中的轻量观测记忆

打开 `wheeltec_exploration/src/observed_obstacle_layer.cpp`、`scripts/observed_map_memory.py` 和 `config/exploration_overrides.yaml`。探索局部层继承原 `costmap_2d::ObstacleLayer`，复用原实时点云、射线清除及 2 s 障碍观测记忆，约 2 Hz 导出膨胀前的三态栅格。局部层启用 `track_unknown_space=true`，避免将默认空白窗口当成已观测区域。

记忆节点将已知格变换到 `map` 后更新 `/nav_static_map`，未知观测不删除历史，新的有效空闲观测可以清除旧障碍；不融合膨胀代价，不新增地面拟合。栅格为 0.05 m，初始 12×12 m，按 2 m 块增长，默认最多 400 万格；超过预算报告失败并由监督器暂停。初始化只发布全未知地图以解除 move_base 初始化依赖，不能作为自动启动证据。正常观测更新发布 `/exploration/map_status`，超过 2 s 无更新暂停目标选择。

旧在线整图刷新器和旧探索高程建图分支已删除。探索不启动PGM map_server或高程服务器，全局仅保留StaticLayer和InflationLayer。原贝叶斯点云积累继续运行，探索设置 `map/autosave_period=0` 禁止周期存盘，正常结束或保存服务仍写PCD/轨迹。最终交付继续按第10节人工执行原 `finalize_map.py`。普通建图保留30 s自动存盘；普通导航默认 `use_observation_memory=false`，原PGM/坡度层和TEB参数保留。旧 `publish_navigation_map`、`map_update_period` 参数不再接受。

复制改动后在 NX 编译并检查入口：

```bash

catkin_make --pkg wheeltec_exploration wheeltec_pointcloud_mapper -j2 -l2
source devel/setup.bash
roslaunch --nodes wheeltec_exploration wheeltec_exploration.launch
```

应看到 `wheeltec_observed_map_memory`，不应看到在线转图、高程服务器或 NDT。该命令只列节点，不会让车移动。

2026-09-11 已在 `.123` 编译，并用旧链路无法起步时录制的静止数据回放 55 s：记忆图更新 99 次，选出 3 个目标，TEB 输出 496 个前进采样、无倒车。记忆节点单次维护平均 9.36 ms、最大 11.01 ms，仅代表该节点，不包含整个感知链耗时。测试使用独立 ROS master，未启动传感器硬件、底盘或安全门，速度仅发布到测试话题；静止里程计会触发目标超时重选，不能用该回放证明实车到达或全屋覆盖。5 项记忆图测试、16 项监督器/前沿测试及普通导航隔离检查通过。下一次实车验收仍按使用文档第 7 节进行。

## 7. 配置正式导航

导航采用两个职责分离的入口。先启动 `wheeltec_system_bringup/launch/wheeltec_localization.launch`，让 Livox、FAST-LIO、NDT、TF 和底盘持续运行；再启动 `wheeltec_navigation/launch/navigation_teb.launch`。后者加载地图、坡度层、当前帧局部地面分割、GlobalPlanner、TEB、起点逃逸插件和 move_base，不得再次包含重定位或底盘节点。

### 7.1 全局 costmap

文件：`wheeltec_navigation/config/global_costmap_slope.yaml`。

```text
StaticLayer(/nav_static_map) -> TerrainCostmapLayer -> InflationLayer
```

- StaticLayer 读取 `map_raw.yaml`，负责自由、占据和未知。
- TerrainCostmapLayer 读取 `terrain_2p5d.yaml`，只在 PGM 已知格上叠加坡度成本。
- InflationLayer 的 `inflation_radius` 为 `0.15 m`，`cost_scaling_factor` 为 `3.0`，用于保证60 cm门在全局栅格上保持连通。
- 全局规划器为 `global_planner/GlobalPlanner`，`allow_unknown: false`。

### 7.2 局部障碍

文件：

```text
wheeltec_terrain_filter/config/patchworkpp_wheeltech.yaml
wheeltec_terrain_filter/config/terrain_guard_wheeltech.yaml
wheeltec_navigation/config/local_costmap_slope.yaml
```

`wheeltec_navigation_patchworkpp` 直接从当前 `/cloud_registered_terrain` 估计地面与非地面，`wheeltec_navigation_terrain_guard` 再按当前局部地面网格输出 `/terrain/obstacle_points` 和 `/terrain/clearing_points`。该链路不查询保存高程，也不依赖全局定位矩阵；局部 costmap 的 `observation_persistence` 为 `0 s`，避免历史点拖影。

局部 costmap 是 `odom` 下 `6 m x 6 m`、`0.05 m` 分辨率的滚动窗口，更新频率 `10 Hz`，膨胀半径 `0.22 m`。

### 7.3 TEB

文件：`wheeltec_navigation/config/teb_local_planner.yaml`。

| 参数 | 值 |
|---|---:|
| `max_vel_x` | 0.20 m/s |
| `max_vel_x_backwards` | 0.15 m/s |
| `max_vel_theta` | 0.40 rad/s |
| `acc_lim_x` | 0.20 m/s2 |
| `acc_lim_theta` | 0.30 rad/s2 |
| `min_obstacle_dist` | 0.04 m，60 cm 门洞模式下的车体边缘净空 |
| `inflation_dist` | 0.15 m，TEB 软代价距离，不是 costmap 膨胀 |

TEB 使用真实 polygon footprint。40 cm宽车体通过60 cm门洞时，每侧物理余量约10 cm；V5.1不增加 footprint padding，并要求4 cm额外动态净空。全局0.15 m膨胀只负责给出连通中心线，局部点云和TEB真实轮廓负责最终碰撞保护。

### 7.4 起点安全逃逸

`StartEscapeRecovery` 只在全局 footprint 碰撞、局部实时 footprint 安全、后方0.30 m走廊预检通过且存在新鲜后向点云覆盖时，以0.05 m/s倒退。倒车过程中持续检查后向覆盖和后方0.10 m，任一条件失效立即停车。当前Mid-360受车体遮挡，实测车后0.15～0.70 m近场为0点，因此未接后置传感器时插件会拒绝自动倒退。配置位于 `move_base_slope_teb.yaml`，源码位于 `wheeltec_2p5d_navigation/src/start_escape_recovery.cpp`。

### 7.5 探索专用组件与参数

打开以下文件，按职责修改：

| 文件 | 修改内容 |
|---|---|
| `wheeltec_exploration/launch/wheeltec_exploration.launch` | 唯一探索入口，组合原建图/导航；默认 `auto_explore=true` |
| `wheeltec_exploration/launch/include/frontier.launch.xml` | 内部前沿适配器和监督器，无重复规划器 |
| `wheeltec_exploration/scripts/explore_supervisor.py` | 就绪后自动申请一次许可；数据暂失时暂停，故障锁停保留现场；仅完成或 Ctrl+C 结束会话，不自动故障复位 |
| `wheeltec_exploration/src/forward_teb_planner.cpp` | 探索专用 TEB 适配：先对准路径，复用原优化器，拒绝倒车轨迹并预检安全门使用的局部停车范围；普通导航仍加载上游插件 |
| `wheeltec_exploration/config/frontier.yaml` | 前沿搜索周期、最小前沿长度和评分权重 |
| `wheeltec_exploration/config/exploration_overrides.yaml` | 探索模式限速、膨胀、障碍保留和约束；不改原 TEB YAML |
| `wheeltec_explore_lite/src/explore.cpp` | 选择真实边界目标，并用原 make_plan 检查可行性 |
| `wheeltec_safety/config/cmd_vel_safety.yaml` | 完整车体轮廓、近场检查和超时；修改前备份 |
| `wheeltec_exploration_driver/src/wheeltec_robot.cpp` | 探索专用串口驱动，含 0.20 s 速度超时停车 |

探索全局/局部膨胀均为 0.10 m，速度上限 0.20 m/s、0.40 rad/s，保留原有局部障碍 2 s 观测记忆。探索加载 `wheeltec_exploration/TebLocalPlannerROS`，参数及话题仍使用 `TebLocalPlannerROS` 命名空间。车头偏离路径超过 1.05 rad 时先原地对准，小于 0.20 rad 后交给原 TEB；倒车轨迹整体退回重规划，不删除线速度后继续转向。`penalty_epsilon=0.005`、`weight_kinematics_forward_drive=10000` 仅用于探索。安全门线速度死区为 0.0001 m/s，不再用 0.011 m/s 死区掩盖倒车。非零指令超时仍锁停。

目标搜索从前沿附近 0.75 m 内选已知区域的候选，目标距离默认至少 0.40 m，避免刚超出到达容差就反复启停。校验完整车体、前向净空和全局路径近处 0.75 m 的局部障碍；`GlobalPlanner/allow_unknown=false`。前沿适配图只用于搜索，实际几何检查读取原全局/局部 costmap，保留坡度和软代价。暂时没有前沿时继续定时检查，不保留旧前沿图用于发目标。

安全门相同内容的消息只刷新接收时间；内容变化会在同一输出周期内重新检查，最多 3 次、预算为周期的 80%。预算耗尽仍输出零；障碍、急停和过期指令仍制动。诊断增加 `latched_reason` 和 `same_cycle_rechecks`，保留首次锁存原因。监督器使用 `/wheeltec_safety/pause`、`resume` 实现地图数据等待；这两个接口不解除故障锁存，也不代替初始 arm。

初始/环形前沿质心可能落在车旁，独立分支改为选择真实边界点，距离至少为 TEB 到达容差加一格分辨率；前沿搜索与长度/距离评分沿用 explore_lite。详见独立包说明。没有候选目标时等待，不据此宣布全屋完成。

会话参数在同一探索 launch：`auto_start=true` 为默认自动开始，`auto_start=false` 为锁定诊断；`completion_hold_time=30.0`、`completion_map_updates=2` 为结束确认条件。适配器发布原子状态 `AVAILABLE/EMPTY/INVALID`，区分无前沿与数据无效；前沿长度阈值读取同一 `/explore/min_frontier_size=0.50 m`。连续有效 EMPTY、无活动目标、两次新观测图成功更新且持续达到确认时间后，监督器先 stop、再停止子进程、保存原 mapper 快照，然后退出。其 `required=true` 使整个探索 launch 收尾；不会自动执行最终 `finalize_map.py NAME`。
