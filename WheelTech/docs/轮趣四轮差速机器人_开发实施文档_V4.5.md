> 平台：Jetson NX、Ubuntu 20.04、ROS Noetic、Livox Mid-360、轮趣四轮差速底盘、Orbbec Gemini 336L。
> 工作空间：`/home/nrc19/livox_fastlio`。
> 本文面向第一次接触本项目的开发者，按“复制什么、打开什么、编译什么、测试什么”组织。

## 1. 当前正式方案

V4.5 保留 Livox、FAST-LIO2、PCD/NDT、PGM、分类点云和高程文件，但导航接口仍是成熟的 ROS1 二维 costmap：

```text
建图
Mid-360 -> FAST-LIO2 -> 完整 PCD -> NDT 地图
                         |
                         +-> 校平点云 -> Patchwork++ -> ground/nonground PCD
                                                     |
                                                     +-> PGM 占据图
                                                     +-> 每格高程、坡度和坡度代价

导航
PCD + NDT -> map->odom
PGM(map_raw) -> 静态占据/未知 ----------------------+
保存的坡度代价 -> TerrainCostmapLayer -------------+-> GlobalPlanner
实时点云 - 保存的同位置地面高程 -> 局部障碍/清除点 -+-> local costmap -> TEB -> /cmd_vel
```

关键约束：

- PGM 决定墙体、固定障碍和未知区域；坡度层只能给 PGM 已知格增加代价，不能把未知格变成自由格。
- 高程地图不是另一套导航入口，而是 PGM 的坡度代价来源和在线点云的地面高度参考。
- 全局规划器是 `global_planner/GlobalPlanner`，局部规划器只使用 TEB；DWA 和旧 `TerrainGlobalPlanner` 不在正式入口中。
- 导航阶段不启动 Patchwork++ 和 terrain_guard。动态障碍根据实时点相对保存地面的高度判定，避免固定 `base_link.z` 截取在坡道上误判。
- 本版本目标是平地、全局斜坡以及平地与坡道组合路段。楼梯语义和跨层地图不属于当前验收范围。

### 5.1 Livox 外参

打开：

```text

车体采用前、左、上坐标。实测 `base_link` 离地 `0.15 m`，雷达离地 `0.30 m`，因此雷达位于车体中心前 `0.10 m`、上 `0.15 m`，雷达朝车头方向下压 `20 deg`。Patchwork++ 的 `sensor_height` 必须填写雷达相对地面的绝对高度 `0.30 m`，不能误填为外参高度 `0.15 m`。两处配置必须表达同一个刚体关系：

y: 0.00
z: 0.15
roll_deg: 0.0
pitch_deg: 20.0

```

`terrain_sensor` 与雷达同原点，但姿态与 `base_link` 一致，用于给 Patchwork++ 提供重力对齐点云。不要把 `terrain_sensor` 再设置成下压 20 度。

## 6. 配置地图生成

### 6.1 唯一建图入口

打开 `wheeltec_system_bringup/launch/wheeltec_mapping.launch`。它必须在同一入口中启动：

1. Mid-360；
2. FAST-LIO2；
3. `wheeltec_pointcloud_mapper`；
4. TF 与 pose adapter；
5. 轮趣串口底盘；
6. `cloud_adapter` 到 `/cloud_registered_terrain`；
7. Patchwork++；
8. ground/nonground 分类 PCD 累积器；`terrain_guard` 仅按需诊断。

正式建图必须共用一套静态点判定，数据流如下：

```text
/cloud_registered
  -> wheeltec_pointcloud_mapper（半径滤波 + 唯一可逆贝叶斯静态判定）
     +-> filtered_camera_init.pcd
     +-> /wheeltec/static_scan (camera_init)
         -> cloud_adapter (terrain_sensor)
         -> Patchwork++
         -> ground/nonground 纯分类累积 PCD
         -> finalize_map.py（以最终贝叶斯 PCD 做 0.05 m 静态门控）
         -> PGM + 2.5D 地图
```

`wheeltec_mapping.launch` 的 `terrain_input_topic` 默认值必须是 `/wheeltec/static_scan`。只有诊断静态滤波时才临时设置为 `/cloud_registered_body`；该回退输入不得用于正式地图。由于静态判定要求至少 25 帧并跨越 4 秒，启动后的前约 `4 s` 没有稳定的分类输出属于正常现象。

地形累积器只负责保存 Patchwork++ 分类结果，不执行静态晋升或第二套贝叶斯判断。`wheeltec_pointcloud_mapper` 是唯一动态/静态权威；三维 DDA 自由射线可以把已确认体素降级，并使整代精细地图点失效。`finalize_map.py` 再把 `raw_camera_init.pcd`（与当前 `filtered_camera_init.pcd` 强制同源）作为最终权威图，通过 `pcd_static_gate_node` 按 `map.voxel_size=0.05 m` 对 ground/nonground 分类点云求体素交集。PGM 和 2.5D 地图只能读取门控后的分类点云。导航阶段继续使用 `/cloud_registered_body` 的实时点云做局部障碍检测，以免移动障碍被静态滤波丢弃。

完整 PCD 和分类 PCD 都自动保存，用户不需要调用手动 finish 服务。

### 6.2 PGM 参数

打开：

```text
wheeltec_map_tools/config/wheeltec_raw.yaml
wheeltec_map_tools/config/wheeltec_nav.yaml
```

正式导航读取 `map_raw.yaml`，静态障碍不预膨胀；costmap 运行时统一膨胀 `0.25 m`。`map.yaml` 兼容图也不再预膨胀，防止保存地图和运行时对同一门框重复膨胀。

分类 PGM 以每格 ground 点的 20% 高度分位数作为地面。nonground 点只有在附近 `0.30 m` 内存在地面，且相对地面高 `0.08-1.50 m`、同格至少 1 点时才成为障碍。该规则用于保留轮高以上的稀疏小障碍，同时排除天花板和无地面支撑的悬空噪声。

### 6.3 高程和坡度参数

打开 `wheeltec_2p5d_navigation/config/terrain_builder.yaml`：

```yaml
resolution: 0.10
ground_height_percentile: 0.20
max_fill_radius_cells: 4
min_fill_neighbors: 3
fit_radius_m: 0.30
smooth_height_delta_m: 0.12
preferred_slope_deg: 5.0
max_slope_deg: 25.0
max_slope_cost: 80
min_lethal_neighbors: 4
```

每格保存一个地面高度；小孔洞只在有足够邻居时填充；局部平面给出坡度；5 度以内不增加坡度成本，5-25 度逐渐增加软代价，持续超过 25 度才成为致命坡度。Patchwork++ nonground 点会在 `0.08-1.50 m` 相对地面高度范围内直接融合进 2.5D 致命障碍，天花板不会进入导航代价。坡面补偿高度残差继续保存为诊断层，不直接判死，避免稀疏点和填洞边缘把平地大面积误判为障碍。

分类点云累积采用 `0.05 m` 三维体素，只累积上游已经确认的静态 ground/nonground 标签，不再设置独立的命中帧数和持续时间。静态资格由 pointcloud mapper 统一要求至少 `25` 次命中、跨 `4.0 s` 且命中率不低于 `70%`；失配后的自由射线可使其降级并从最终地图失效。PGM 投影每个 `0.05 m` 栅格至少需要 `2` 个有效障碍点，以降低单点噪声，同时保留低矮障碍。

## 7. 配置正式导航

导航采用两个职责分离的入口。先启动 `wheeltec_system_bringup/launch/wheeltec_localization.launch`，让 Livox、FAST-LIO、NDT、TF 和底盘持续运行；再启动 `wheeltec_navigation/launch/navigation_teb.launch`。后者只加载地图、坡度层、实时高程相对障碍、GlobalPlanner、TEB 和 move_base，不得再次包含重定位或底盘节点。

### 7.1 全局 costmap

文件：`wheeltec_navigation/config/global_costmap_slope.yaml`。

```text
StaticLayer(/nav_static_map) -> TerrainCostmapLayer -> InflationLayer
```

- StaticLayer 读取 `map_raw.yaml`，负责自由、占据和未知。
- TerrainCostmapLayer 读取 `terrain_2p5d.yaml`，只在 PGM 已知格上叠加坡度成本。
- InflationLayer 的 `inflation_radius` 为 `0.25 m`，`cost_scaling_factor` 为 `3.0`。
- 全局规划器为 `global_planner/GlobalPlanner`，`allow_unknown: false`。

### 7.2 局部障碍

文件：

```text
wheeltec_2p5d_navigation/config/terrain_relative_obstacle.yaml
wheeltec_navigation/config/local_costmap_slope.yaml
```

`terrain_relative_obstacle_node` 把实时点变换到 `map`，查询同一 XY 附近保存的地面高程：

- 相对地面 `0.08-1.50 m`：发布到 `/terrain/elevation_obstacle_points`；
- 相对地面 `-0.25-2.00 m`：发布到 `/terrain/elevation_clearing_points`；
- 地图中没有可信地面高度：不发布 marking，也不把未知区域清空。

局部 costmap 是 `odom` 下 `6 m x 6 m`、`0.05 m` 分辨率的滚动窗口，更新频率 `10 Hz`，膨胀半径 `0.25 m`。

### 7.3 TEB

文件：`wheeltec_navigation/config/teb_local_planner.yaml`。

| 参数 | 值 |
|---|---:|
| `max_vel_x` | 0.20 m/s |
| `max_vel_x_backwards` | 0.15 m/s |
| `max_vel_theta` | 0.40 rad/s |
| `acc_lim_x` | 0.20 m/s2 |
| `acc_lim_theta` | 0.30 rad/s2 |
| `min_obstacle_dist` | 0.08 m，60 cm 门洞模式下的车体边缘净空 |
| `inflation_dist` | 0.20 m，TEB 软代价距离，不是 costmap 膨胀 |

TEB 使用真实 polygon footprint。40 cm 宽车体通过 60 cm 门洞时，TEB 每侧保留 `0.08 m` 净空，理论剩余余量约为两侧各 `0.02 m`；costmap 另使用 `0.02 m` footprint padding 做碰撞检查。不得缩小真实 footprint；若实测门洞、轮胎外沿或地图墙厚不同，应优先重新测量，并保持低速通过。
