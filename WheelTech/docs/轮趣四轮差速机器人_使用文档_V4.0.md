# 轮趣四轮差速机器人使用文档 V4.0

> 本文只讲日常使用：检查、Gemini 336L 相机、建图、保存、定位、导航、上位机控制和停止。  
> 安装与改代码见《开发实施文档》，话题和参数见《详细信息表》。
> V4.0（2026-09-01）保留原始点云处理、PCD/NDT 定位和 PGM 输出，正式导航改为持久化 2.5D 地图、2.5D 全局规划与 TEB 局部规划；DWA 不再提供。

## 1. 开机检查

登录 NX：

~~~bash
ssh nrc19@192.168.50.122
source /home/nrc19/livox_fastlio/devel/setup.bash
~~~

检查雷达：

~~~bash
ip -4 addr show dev eth0
ping -c 2 192.168.1.165
~~~

检查底盘：

~~~bash
lsusb
ls -l /dev/ttyACM0 /dev/wheeltec_controller
~~~

检查相机：

~~~bash
lsusb | grep 2bc5:0807
~~~

通过条件：

- eth0 包含 192.168.1.5/24；
- 雷达 192.168.1.165 可达；
- /dev/wheeltec_controller 指向 ttyACM0；
- 能看到 `2bc5:0807` Orbbec Gemini 336L；
- 急停可用，车辆周围安全。

## 2. Gemini 336L 相机

### 2.1 一键启动

相机可以独立启动，不会启动底盘，也不会让车辆运动：

~~~bash
source /home/nrc19/livox_fastlio/devel/setup.bash
roslaunch wheeltec_system_bringup wheeltec_orbbec336l.launch
~~~

正式入口默认开启 RGB、深度、无颜色点云、相机内部 TF 和 `base_link→camera_link` 安装 TF。正式外参为前 `0.16 m`、左 `0 m`、上 `0.08 m`，相机与车体同姿态，即 `roll=pitch=yaw=0`。若只想测试驱动而不接入整车 TF，可运行：

~~~bash
roslaunch wheeltec_system_bringup wheeltec_orbbec336l.launch \
  publish_mount_tf:=false
~~~

### 2.2 检查设备与数据

另开终端：

~~~bash
source /home/nrc19/livox_fastlio/devel/setup.bash
rosservice call /camera/get_device_info
rosservice call /camera/get_sdk_version
rostopic hz /camera/color/image_raw
rostopic hz /camera/depth/image_raw
rostopic hz /camera/depth/points
~~~

| 输出 | 实机期望 |
|---|---|
| RGB | `/camera/color/image_raw`，1280×720 MJPG，30 Hz |
| 深度 | `/camera/depth/image_raw`，848×480 Y16，约 30 Hz |
| 点云 | `/camera/depth/points`，约 30 Hz |
| 设备 | Gemini 336L，USB 3.2，固件 1.4.60 |
| SDK / Wrapper | 2.9.3 / 2.9.3 |

驱动按需启流：只有订阅者连接后才持续传输对应图像或点云，因此刚启动时没有带宽占用或 `rostopic hz` 数据不是故障。

### 2.3 查看图像和 TF

上位机已经接入 NX ROS Master 时，可使用：

~~~bash
rqt_image_view /camera/color/image_raw
rqt_image_view /camera/depth/image_raw
rviz
~~~

RViz 点云显示选择 `/camera/depth/points`，Fixed Frame 先用 `camera_depth_optical_frame`。安装外参写入后检查：

~~~bash
rosrun tf tf_echo base_link camera_link
rosrun tf tf_echo camera_link camera_color_optical_frame
rosrun tf tf_echo camera_link camera_depth_optical_frame
~~~

第一条应等于相机相对车体的实测位置和姿态；后两条由 Orbbec 驱动发布，不要手工覆盖。车体坐标为前 `+X`、左 `+Y`、上 `+Z`，位置单位米，角度单位弧度。

### 2.4 停止

在相机启动终端按一次 `Ctrl+C`，等待 `/camera/camera` 退出。不要在写图像或点云时拔线。

## 3. 建图

### 3.1 启动

地图名不要使用空格，也不要复用已经存在的正式地图目录。V4.0 只保留一个建图入口：

~~~bash
roslaunch wheeltec_system_bringup wheeltec_mapping.launch \
  map_name:=factory_a
~~~

该入口同时运行完整三维 PCD 建图、水平点云适配、Patchwork++、terrain_guard 和 2.5D 分类地图累积；FAST-LIO 与 NDT 所需数据仍按原流程生成，不再另设 terrain 建图入口。

禁止继续使用修复前生成的 `factory_terrain_a`：该地图曾在前倾20°的 `body` 中计算坡度，平地被大量写成静态障碍，重新执行 finalize 也无法恢复。必须使用修复后的程序重新采集并使用新地图名。

如果确实要覆盖同名地图，先确认旧地图已经在本地备份；`finalize_map.py` 默认保留已经存在的 `raw_camera_init.pcd`，只有明确使用 `--replace-raw` 才会替换它。

### 3.2 检查频率

另开终端：

~~~bash
source /home/nrc19/livox_fastlio/devel/setup.bash
rostopic hz /livox/lidar /livox/imu /Odometry \
  /cloud_registered /odom
~~~

同时检查地形分支：

~~~bash
rostopic hz /terrain/ground_points \
  /terrain/obstacle_points \
  /terrain/clearing_points
rostopic echo -n 1 /cloud_registered_terrain/header
rosrun tf tf_echo base_link terrain_sensor
rostopic echo -n 1 /terrain/status
~~~

`/cloud_registered_terrain/header.frame_id` 和分类点云 frame 必须是 `terrain_sensor`。若为 `body`，立即停止建图；否则水平地面会接近20°阈值并污染分类地图。

`tf_echo` 应显示约 `[0.10,0,0.15] m` 且旋转为零。这里的20°只存在于雷达 `body` 外参，不能再次施加到 `terrain_sensor`。

| 话题 | 期望 |
|---|---:|
| /livox/lidar | 约 10 Hz |
| /livox/imu | 约 200 Hz |
| /Odometry | 约 10 Hz |
| /cloud_registered | 约 10 Hz |
| /odom | 约 20 Hz |

### 3.3 驾驶采集

- 低速、匀速；
- 避免急刹和高速原地旋转；
- 从不同方向覆盖门口、墙面、拐角；
- 尽量形成闭合路线；
- 避免人员在雷达前长时间停留；
- 雷达松动后必须停止，本次地图不可继续使用。

### 3.4 停止并保存

建图过程中，过滤后的静态 PCD 每 30 秒自动保存一次。完成采集后，在建图终端按一次 `Ctrl+C` 并等待节点正常退出；退出时会再保存一次。不要使用 `kill -9`，不要在保存时断电。

节点退出后，单独生成交付地图：

~~~bash
rosrun wheeltec_map_tools finalize_map.py factory_a
~~~

地图名必须与建图启动参数保持一致。命令完成时应显示 `[DONE] map finalized`。该工具读取自动保存的完整与分类 PCD，一次生成 NDT PCD、兼容 PGM/YAML 和 2.5D 六层地图。

检查：

~~~bash
find /home/nrc19/livox_fastlio/maps/factory_a \
  -maxdepth 1 -type f -printf '%f %s bytes\n' | sort
~~~

应有：

~~~text
filtered_camera_init.pcd
raw_camera_init.pcd
public_map.pcd
map_raw.pgm
map_raw.yaml
map.pgm
map.yaml
map_metadata.yaml
~~~

terrain 模式还应有：

~~~text
terrain_ground_camera_init.pcd
terrain_obstacles_camera_init.pcd
terrain_ground_map.pcd
terrain_obstacles_map.pcd
terrain_cost.pgm
terrain_cost.yaml
terrain_2p5d.yaml
terrain_2p5d_elevation.f32
terrain_2p5d_slope_deg.f32
terrain_2p5d_roughness.f32
terrain_2p5d_step_height.f32
terrain_2p5d_cost.u8
terrain_2p5d_confidence.u8
~~~

`public_map.pcd` 继续用于 NDT 重定位，`map.pgm/map_raw.pgm` 继续用于 RViz 和二维兼容链路，`terrain_cost.yaml` 仅保留为兼容输出。V4.0 的规划主地图是 `terrain_2p5d.yaml` 及六个二进制栅格层，分别保存每格高程、坡度、粗糙度、台阶残差、通行代价和置信度。坡面是带代价的可通行区域，连续台阶/障碍为致命区域；0.32 m 车体包络参与全局搜索，避免只看车体中心而出现半车上坡、半车贴平面的路径。

## 4. 定位

~~~bash
roslaunch wheeltec_system_bringup wheeltec_localization.launch \
  map_name:=factory_a
~~~

等待 FAST-LIO 初始化。在 RViz 使用 2D Pose Estimate：

1. 点击小车在地图中的大致位置；
2. 拖动箭头指向车头；
3. 查看实时点云是否与地图墙面、门框重合。

检查：

~~~bash
rostopic echo -n 1 /map_cloud/header
rostopic echo -n 1 /cloud_registered_base/header
rosrun tf tf_echo map base_link
~~~

通过：

~~~text
map_cloud.frame_id = map
cloud_registered_base.frame_id = base_link
map→base_link 连续
~~~

启动最初数秒 TF 未连接通常是 IMU 初始化；持续断开才是故障。

## 5. 导航

V4.0 只保留原有名称的正式导航入口，它同时启动 PCD/NDT 定位、2.5D 地图服务器、2.5D 全局规划和 TEB：

~~~bash
roslaunch wheeltec_navigation navigation_teb.launch \
  map_name:=factory_terrain_b
~~~

日常导航不要提前单独启动 `wheeltec_localization.launch`，否则会重复启动 Livox、FAST-LIO、底盘和定位节点。`wheeltec_localization.launch` 仅供开发者单独排查重定位。正式入口必须读取 `maps/NAME/terrain_2p5d.yaml`；文件不存在时重新执行 `finalize_map.py NAME`，不能用 `terrain_cost.yaml` 或 `map_raw.yaml` 冒充。正式局部规划器只有 TEB，V4.0 不包含 DWA。

发送目标前检查：

~~~bash
rostopic hz /odom
rostopic info /cloud_registered_body
rostopic hz /cloud_registered_terrain
rostopic echo -n 1 /terrain_2p5d/elevation_cloud/header
rostopic echo -n 1 /terrain_2p5d/traversability_cost/info
rosrun tf tf_echo map base_link
~~~

必须满足：

- map_name 与定位一致；
- /odom 约 20 Hz；
- 原始模式下 move_base 订阅 `/cloud_registered_body`；terrain 模式下同时收到 `/terrain/obstacle_points` 和 `/terrain/clearing_points`；
- terrain 模式下 `/cloud_registered_terrain` 与分类点云的 frame 必须为 `terrain_sensor`，不能为倾斜的 `body`；
- `/terrain_2p5d/traversability_cost` 中平地代价低、坡面为中间代价、危险台阶/障碍为100；
- map→base_link 稳定；
- 急停可用；
- 已通知现场人员车辆将运动。

在 RViz 使用 2D Nav Goal。首次在新地图只发送短距离、开阔区域目标。

### 5.1 Terrain 测试顺序

先不发目标，只观察：

~~~bash
rostopic hz /terrain/obstacle_points /terrain/clearing_points
rosparam get /move_base/local_costmap/obstacle_layer/observation_sources
rostopic echo -n 1 /move_base/local_costmap/costmap
rosparam get /move_base/base_global_planner
rosparam get /move_base/base_local_planner
~~~

参数必须显示：

~~~text
terrain_marking terrain_clearing
wheeltec_2p5d_navigation/TerrainGlobalPlanner
teb_local_planner/TebLocalPlannerROS
~~~

再按以下顺序低速测试：

1. 平地短距离直行；
2. 平地孤立箱体停车和绕行；
3. 坡道入口前停车观察 costmap；
4. 低速进入坡中；
5. 通过坡顶/坡底过渡区；
6. 楼梯前停车，禁止首次测试直接驶向楼梯边缘。

出现以下任一情况立即取消目标、发布零速度并停止 2.5D 导航排查：

- terrain 输出低于约 8 Hz 或中断；
- 整片正常坡道持续显示为致命障碍，或轨迹上的高程连通性被错误切断；
- 楼梯、断差在 local costmap 中被连续释放；
- `/cmd_vel` 与局部路径方向异常；
- 定位点云与地图明显错位。

### 5.2 RViz观察与测试记录

首次 terrain 测试建议在 RViz 增加以下 `PointCloud2`：

| 显示名 | 话题 | 建议颜色 | 含义 |
|---|---|---|---|
| Ground | `/terrain/ground_points` | 绿色 | 当前允许通行的候选地面 |
| UnsafeGround | `/terrain/unsafe_ground_points` | 橙色 | 坡度、台阶或粗糙度超限地面 |
| Obstacles | `/terrain/obstacle_points` | 红色 | 实际送入local costmap的标障点 |
| Unknown | `/terrain/unknown_points` | 灰色 | 无可靠参考、未用于标障的点 |

静止观察时 Fixed Frame 使用 `terrain_sensor`；结合定位和costmap观察时使用 `map` 或 `odom`。不要用倾斜的 `body` 判断坡度。红点中的 z 已统一为0.20 m，这是二维costmap标障高度，不代表障碍物真实三维高度。

测试前另开终端记录必要数据：

~~~bash
mkdir -p /home/nrc19/livox_fastlio/test_bags
cd /home/nrc19/livox_fastlio/test_bags
rosbag record --lz4 -O terrain_test \
  /cloud_registered_body /cloud_registered_terrain /Odometry /odom \
  /tf /tf_static \
  /terrain/ground_points \
  /terrain/unsafe_ground_points \
  /terrain/obstacle_points \
  /terrain/clearing_points \
  /terrain/unknown_points \
  /terrain/status \
  /move_base/status \
  /terrain_2p5d/elevation_cloud \
  /terrain_2p5d/traversability_cost \
  /terrain_2p5d/slope \
  /move_base/TebLocalPlannerROS/local_plan \
  /cmd_vel
~~~

测试结束用一次 `Ctrl+C` 正常关闭 rosbag。未正常关闭产生 `.bag.active` 时不要直接作为正式测试数据，先运行 `rosbag reindex`，并按实际有效时长裁剪或只回放有效区间。

当前软件限制：

| 项目 | 值 |
|---|---:|
| 前进 | 0.35 m/s |
| 倒车 | 0.15 m/s |
| 角速度 | 0.80 rad/s |
| 线加速度 | 0.20 m/s² |
| 角加速度 | 0.30 rad/s² |

## 6. 上位机 ROS

上位机与 NX 在同一网络：

~~~bash
export ROS_MASTER_URI=http://192.168.50.122:11311
export ROS_IP=<上位机IP>
~~~

读取：

~~~bash
rostopic echo /odom
rostopic echo /imu
rostopic echo /PowerVoltage
rostopic echo -n 1 /camera/color/camera_info
rostopic echo -n 1 /camera/depth/camera_info
~~~

人工控制只使用 linear.x 和 angular.z，linear.y 必须为 0。

运动前必须告知现场，清空车辆周围并准备急停。

低速示例：

~~~bash
rostopic pub -r 10 /cmd_vel geometry_msgs/Twist \
  '{linear: {x: 0.05, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
~~~

按 Ctrl+C 后发布零速度：

~~~bash
rostopic pub -1 /cmd_vel geometry_msgs/Twist \
  '{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
~~~

## 7. 停止顺序

1. 停止发送目标或人工速度；
2. 发布一次零速度；
3. 停止 navigation；
4. 停止 localization；
5. 停止相机 launch，等待 `/camera/camera` 退出；
6. 建图模式先正常 Ctrl+C 停止并等待自动保存，再运行 finalize_map.py；
   地图收尾必须使用与建图入口相同的地图名；2.5D 输出已是默认行为；
7. 用 rosnode list 确认业务节点已退出；
8. 最后关闭底盘、雷达和相机供电。

## 8. 快速排错

| 现象 | 首先检查 |
|---|---|
| 无雷达点云 | eth0、192.168.1.165、网线、/livox/lidar |
| 无底盘 odom | lsusb、ttyACM0、udev、USB 供电 |
| `lsusb` 无 2bc5:0807 | USB 3.0 数据线、接口、供电、重新插拔 |
| 有相机节点但图像无数据 | 先运行 `rostopic hz` 建立订阅；再查 USB、节点日志和流开关 |
| 相机节点链接时报 `cv::Mat` | OpenCV 头文件和运行库必须同为 4.2.0；按开发实施文档修复 |
| 点云方向或位置错误 | `base_link→camera_link` 安装外参；不要修改 optical frame |
| FAST-LIO 无输出 | /livox/lidar、/livox/imu、初始化日志 |
| 点云直行时升降 | base_link→body 的 Pitch、雷达是否松动 |
| terrain 没有输出 | `/cloud_registered_body`→`/cloud_registered_terrain`→Patchwork++→terrain_guard→TF与节点日志 |
| 正常坡道被整片标障 | 输入必须为`terrain_sensor`→`base_link→terrain_sensor` RPY必须为0→禁止使用修复前地图→22°阈值→坡道实测坡度 |
| 楼梯未被阻挡 | `/terrain/unsafe_ground_points`→台阶相邻栅格→local costmap marking source→立即停止实车测试 |
| terrain 地图大面积发黑 | `terrain_sensor`校平→是否误用修复前分类PCD→无参考最低障碍高度0.03 m→静态障碍5帧/1 s门槛→重新采集 |
| 无全局路径且车不动 | `/move_base/status`和日志→起点/目标是否落入100代价→分类地图是否污染；这不是底盘故障 |
| NDT 不收敛 | 地图名、初值、base_link 点云、外参 |
| TF 持续断开 | TF 唯一发布者、节点存活、系统时间 |
| 有路径车不动 | /cmd_vel、/odom、串口、急停 |
| 地图文件不全 | filtered_camera_init.pcd 是否存在、finalize_map.py 输出、目录权限和磁盘 |

## 9. 安全规则

- 未通知现场人员，不发布非零 /cmd_vel；
- 首次测试使用约 0.05 m/s 和数秒级时间；
- 不在台阶、斜坡边缘和人员密集区域首次测试；
- terrain 首次验收必须有人持急停，楼梯测试只允许从安全距离接近并停车观察；
- `/terrain/obstacle_points` 或 `/terrain/clearing_points` 中断时不得继续 terrain 导航；
- 定位未收敛时不发送导航目标；
- 雷达或外参变化后不使用旧地图；
- 相机安装位置变化后重新测量 `base_link→camera_link`；当前正式值为平移 `[0.16,0,0.08] m`、RPY `[0,0,0] rad`；
- 测试结束必须发布零速度。
