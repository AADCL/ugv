# 轮趣四轮差速机器人使用文档 V4.5

> 本文只讲日常操作。安装、复制源码和开发验收见《开发实施文档 V4.5》；全部节点、话题和参数见《详细信息表 V4.5》。

## 1. 当前功能

正式系统只有一个建图入口和一个导航入口：

```text
建图：Livox + FAST-LIO2 + PCD + Patchwork++ 分类 -> PGM + 保存高程/坡度
导航：PCD/NDT 重定位 + PGM 占据 + 坡度软代价 + 高程相对障碍 + TEB
```

PGM 仍是全局占据/未知地图。高程文件用于给全局路径增加坡度代价，并让局部障碍检测随地面起伏变化。系统面向平地、整体斜坡和局部坡道组合；当前不承诺识别或通行楼梯。

## 2. 开机检查

登录并加载工作空间：

```bash
ssh nrc19@192.168.50.122
source /home/nrc19/livox_fastlio/devel/setup.bash
```

检查 Livox 网络：

```bash
ip -4 addr show dev eth0
ping -c 2 192.168.1.165
```

检查底盘控制器：

```bash
lsusb
ls -l /dev/ttyACM0 /dev/wheeltec_controller
```

检查相机（需要相机时）：

```bash
lsusb | grep 2bc5:0807
```

开始操作前应满足：

- `eth0` 有 `192.168.1.5/24`；
- Mid-360 `192.168.1.165` 可达；
- `/dev/wheeltec_controller` 存在；
- 急停可用，车辆周围没有人员或易损物；
- mapping 不与定位/导航同时运行；定位只启动一次，导航随后叠加。

## 3. 相机

Gemini 336L 可独立启动，不会主动控制底盘：

```bash
roslaunch wheeltec_system_bringup wheeltec_orbbec336l.launch
```

检查：

```bash
rostopic hz /camera/color/image_raw
rostopic hz /camera/depth/image_raw
rostopic hz /camera/depth/points
rosrun tf tf_echo base_link camera_link
```

安装外参应为前 `0.16 m`、左 `0 m`、上 `0.08 m`，姿态与车体一致。驱动按需启流，没有订阅者时图像或点云暂时不传输属于正常行为。

## 4. 建图

### 4.1 启动

地图名只使用字母、数字和下划线，不要复用已有正式地图：

```bash
roslaunch wheeltec_system_bringup wheeltec_mapping.launch \
  map_name:=factory_a
```

这个入口同时启动完整 PCD 建图和分类地面建图，不需要再启动另一套 2.5D launch。两类地图共用 `/wheeltec/static_scan`：它由 `wheeltec_pointcloud_mapper` 对 `/cloud_registered` 做半径滤波和可逆贝叶斯静态判定后发布。分类累积器只保存 ground/nonground 标签，不再重复判断静态资格；最终转换以 `filtered_camera_init.pcd` 为静态权威图，按 `0.05 m` 体素门控分类点云，清除已经不属于最终贝叶斯静态图的人员轨迹和临时障碍。正式建图默认不启动仅用于诊断的 `terrain_guard`。

启动后，点至少命中 `25` 次、观测跨度达到 `4.0 s` 且命中率不低于 `70%` 才会晋升为静态点；此前静态点及分类话题为空或点数较少属于正常现象。正式建图不要覆盖默认输入。只有排障对比时可临时运行：

```bash
roslaunch wheeltec_system_bringup wheeltec_mapping.launch \
  map_name:=debug_raw_terrain \
  terrain_input_topic:=/cloud_registered_body
```

该回退模式绕过静态滤波，不能用于正式交付地图。

### 4.2 确认数据

另开终端：

```bash
source /home/nrc19/livox_fastlio/devel/setup.bash
rostopic hz /livox/lidar
rostopic hz /livox/imu
rostopic hz /Odometry
rostopic hz /cloud_registered
rostopic hz /wheeltec/static_scan
rostopic hz /cloud_registered_terrain
rostopic hz /terrain/patchwork_ground
rostopic hz /terrain/patchwork_nonground
```

点云通常约 10 Hz。检查 TF：

```bash
rosrun tf tf_echo camera_init body
rosrun tf tf_echo body base_link
rosrun tf tf_echo base_link terrain_sensor
```

### 4.3 采集路线

低速行驶并覆盖：

1. 起点周围和房间边界；
2. 可通行平地；
3. 坡底、坡中、坡顶；
4. 坡道两侧和回程方向；
5. 计划以后放置导航目标的区域。

高程地图只对实际观察到的地面可靠。单向快速经过坡道容易产生孔洞，应低速往返并让相邻扫描有重叠。

### 4.4 停止与自动保存

先让车辆完全停止，再在建图终端按一次 `Ctrl+C`，等待节点退出。完整 PCD 和分类 PCD 会周期保存并在正常退出时再保存，不需要手动调用 finish。

检查原始产物：

```bash
ls -lh /home/nrc19/livox_fastlio/maps/factory_a
```

至少应有：

```text
filtered_camera_init.pcd
terrain_ground_camera_init.pcd
terrain_obstacles_camera_init.pcd
```

### 4.5 生成正式地图

```bash
source /home/nrc19/livox_fastlio/devel/setup.bash
rosrun wheeltec_map_tools finalize_map.py factory_a
```

正常结束会打印 `[DONE] map finalized`。再次检查：

```bash
MAP_DIR=/home/nrc19/livox_fastlio/maps/factory_a
ls -lh "$MAP_DIR"
```

必须存在：

```text
public_map.pcd
map_raw.pgm
map_raw.yaml
map.pgm
map.yaml
terrain_ground_static_camera_init.pcd
terrain_obstacles_static_camera_init.pcd
terrain_ground_map.pcd
terrain_obstacles_map.pcd
terrain_2p5d.yaml
terrain_2p5d_elevation.f32
terrain_2p5d_slope_deg.f32
terrain_2p5d_roughness.f32
terrain_2p5d_step_height.f32
terrain_2p5d_cost.u8
terrain_2p5d_confidence.u8
map_metadata.yaml
```

`map_raw.yaml` 是正式导航静态图；`map.yaml` 是不带离线障碍膨胀的兼容图。`terrain_*_static_camera_init.pcd` 是经过最终静态权威图门控的分类中间结果，后续 PGM 和 2.5D 文件只允许从这两份点云生成。障碍只由 move_base 在运行时膨胀 `0.25 m`，避免保存地图和运行时重复膨胀。不要删除任何 `terrain_2p5d_*` 文件，它们与 YAML 是一个整体。

如果目录中已有 `raw_camera_init.pcd`，转换工具会逐字节检查它是否与当前 `filtered_camera_init.pcd` 相同。不同则立即退出，防止把上一次建图的静态权威图与本次分类点云混合；只有明确替换整套地图时才使用 `--replace-raw`。

建图时，高于局部地面 `0.08-1.50 m` 的 nonground 点会写入 PGM 和 2.5D 致命障碍。分类累积器以 `0.05 m` 体素保存上游已确认的静态标签，不再自行做不可逆的命中帧判定；最终转换还会与贝叶斯静态权威 PCD 求体素交集。坡面补偿高度残差只用于诊断，不直接判死；连续坡面仍按坡度软代价处理。

## 5. 只运行重定位

仅观察定位、不启动导航时：

```bash
roslaunch wheeltec_system_bringup wheeltec_localization.launch \
  map_name:=factory_a
```

在 RViz 使用 `2D Pose Estimate` 发布初始位姿。检查：

```bash
rosrun tf tf_echo map odom
rostopic hz /cloud_registered_base
rostopic echo -n 1 /map_2d/info
```

出现稳定的 `map -> odom` 后才算重定位成功。准备启动导航时保持这个终端和定位入口运行，不要再次启动第二个 localization。

## 6. 正式导航

### 6.1 启动纯导航层

```bash
roslaunch wheeltec_navigation navigation_teb.launch \
  map_name:=factory_a
```

该命令必须在第 5 节的定位入口已经稳定运行后执行。它只启动 PGM、高程/坡度服务器、实时高程相对障碍过滤、GlobalPlanner、TEB 和 move_base，不会启动或替换 Livox、FAST-LIO、NDT 与底盘节点。定位与导航使用同一个 `map_name`。

两个终端的正确关系：

```text
终端1：wheeltec_localization.launch   # 持续运行，只启动一次
终端2：navigation_teb.launch          # 纯导航层
```

### 6.2 发送目标前检查

```bash
rosnode list | grep -E 'move_base|global_localizer|terrain_relative|map_server'
rosparam get /move_base/base_global_planner
rosparam get /move_base/base_local_planner
rosparam get /move_base/global_costmap/inflation_layer/inflation_radius
rosparam get /move_base/local_costmap/inflation_layer/inflation_radius
rostopic hz /terrain/elevation_obstacle_points
rostopic hz /terrain/elevation_clearing_points
```

应看到：

```text
global_planner/GlobalPlanner
teb_local_planner/TebLocalPlannerROS
0.25
0.25
```

如果两个 elevation 点云没有频率，先检查 `map -> terrain_sensor` TF、`terrain_2p5d.yaml` 和 FAST-LIO 点云，不要发送目标。

坡度图用于解释全局路径偏好，不取代 PGM。PGM 未知区域仍不可达。

### 6.4 首次测试顺序

每次运动前告知现场人员并确认急停。目标按以下顺序逐步扩大：

1. 平地前方 0.5 m；
2. 平地前方 1.0 m；
3. 绕开单个固定障碍；
4. 坡底到坡中；
5. 坡中到坡顶；
6. 平地和坡道组合路线。

看到路径不等于可以放行。还要确认局部 costmap 未把坡面填满、TEB 有 local plan、`/cmd_vel` 连续且方向正确。

```bash

```

底盘接受 `/cmd_vel` 的 `linear.x` 和 `angular.z`。直接测试前必须抬轮或清空场地并告知现场人员：

```bash

```

## 8. 停止顺序

1. 在 RViz 取消当前导航目标；
2. 发布一次零速度；
3. 停止导航日志并等待 bag 收尾；
4. 停止导航或定位 launch；
5. 确认 `/cmd_vel` 没有其他发布者；
6. 最后关闭底盘和传感器电源。

检查发布者：

```bash
rostopic info /cmd_vel
```

## 9. 快速排错

| 现象 | 处理 |
|---|---|
| `/dev/wheeltec_controller` 不存在 | 换回支持数据的 USB 线；检查 `lsusb`、`dmesg -w`、udev 和 dialout 组 |
| 启动导航后没有 `map` TF | 发布 `/initialpose`；检查 `public_map.pcd`、NDT 输入和 global localizer 日志 |
| 全屋都是不可通行 | 对比 `/nav_static_map` 与原 PGM；检查地图是否由当前版本重新 finalize；查看坡度层是否覆盖未知格 |
| 有全局路径但不走 | 查看 TEB local plan、局部 costmap、footprint、门洞实测净宽及车体是否对正 |
| 坡道进入局部图后全是障碍 | 检查使用的高程地图是否与当前定位地图同名；检查 map TF 与相对高度点云 |
| 没有坡度/高程话题 | `terrain_2p5d.yaml` 或其二进制层缺失，重新执行 finalize |
| 目标在灰色未知区 | 重新采集覆盖该区域；不要开启 `allow_unknown` 绕过地图缺失 |
| 点云频率正常但定位跳动 | 检查初始位姿、PCD 坐标系、雷达外参和时间戳 |

## 10. 参数说明

- costmap `inflation_radius=0.25 m`、`cost_scaling_factor=3.0`：障碍栅格的运行时软代价范围与衰减速度。
- footprint：机器人真实几何轮廓，当前为 `0.50 m x 0.40 m`，另有 `0.02 m` padding。
- TEB `min_obstacle_dist=0.08 m`：60 cm 门洞模式下车体边缘希望保持的净空。
- TEB `inflation_dist=0.20 m`：轨迹优化的软代价距离，不是 costmap 膨胀半径。

40 cm 宽车体通过 60 cm 门洞只有约 10 cm/侧物理余量；考虑 padding、TEB 净空和地图误差后余量更小。进入门前应尽量正对门洞，低速通过。地图中的门洞净宽不足以容纳完整 footprint 和净空时，规划器拒绝通过是正确的碰撞保护。

四者含义不同。缩小 costmap 膨胀不会缩小真实车体，也不会让 TEB 无视碰撞。

## 11. 安全规则

- 未告知现场人员前，不发送 `/cmd_vel` 或导航目标。
- 首次测试不在坡边、台阶边缘、狭窄通道或人员附近进行。
- 重定位未稳定、TF 断裂、局部图大面积占据或 TEB 无局部路径时立即取消目标。
- 不同时运行两个底盘节点或两个 Livox 驱动；mapping 不与定位/导航同时运行。
- 导航测试必须是一个 localization 加一个 navigation，不能启动第二个 localization。
- 原始地图、PCD、rosbag 和日志不提交 GitHub。
