## 3. 外参与 TF

base_link→body：

| x | y | z | roll | pitch | yaw |
|---:|---:|---:|---:|---:|---:|
| +0.10 m | 0 | +0.15 m | 0° | +20° | 0° |

坐标约定：前、左、上。

| TF | 类型 | 唯一发布者 |
|---|---|---|
| map→odom | 动态 | wheeltec_global_localizer |
| odom→camera_init | 静态 | wheeltec_geometry_tf_publisher |
| camera_init→body | 动态 | FAST-LIO2 |
| body→base_link | 静态 | wheeltec_tf_manager |
| base_link→terrain_sensor | 静态 | wheeltec_tf_manager；平移 `[0.10,0,0.15] m`，RPY `[0,0,0]` |
| base_link→camera_link | 静态 | wheeltec_camera_mount_tf；平移 `[0.16,0,0.08] m`，RPY `[0,0,0] rad` |
| camera_link→camera_*_optical_frame | 静态 | Orbbec 驱动 |

实车验证：约 0.26 m 前进/倒车闭环后 Z 残差约 1.6 mm，保留 Pitch +20°。

## 4. 正式入口

| 模式 | 命令 | 说明 |
|---|---|---|
| 建图 | `roslaunch wheeltec_system_bringup wheeltec_mapping.launch map_name:=NAME` | 唯一正式建图入口；同时生成完整 PCD 和 2.5D 分类累积数据 |
| 地图最终生成 | `rosrun wheeltec_map_tools finalize_map.py NAME` | 读取 mapper 保存的 PCD，生成定位与导航地图资产 |
| 2.5D 地图最终生成 | `rosrun wheeltec_map_tools finalize_map.py NAME --terrain` | 保留完整 PCD/NDT 和 PGM，并生成 `terrain_2p5d.yaml`、六层持久化栅格及兼容 `terrain_cost.yaml` |
| 定位 | `roslaunch wheeltec_system_bringup wheeltec_localization.launch map_name:=NAME` | Livox、FAST-LIO、TF、NDT、两套地图、底盘 |
| 导航 | `roslaunch wheeltec_navigation navigation_teb.launch map_name:=NAME` | 唯一正式导航入口；PCD/NDT 定位 + 2.5D 地图/全局规划 + TEB |
| 导航日志 | `roslaunch wheeltec_navigation nav_logging.launch tag:=TAG` | 定位和导航启动后运行，Ctrl+C 完成 bag 与分析 |
| Livox+底盘基础链路 | `roslaunch wheeltec_system_bringup wheeltec_livox_base.launch` | 只验证雷达驱动和串口底盘 |
| FAST-LIO+TF+底盘 | `roslaunch wheeltec_system_bringup wheeltec_system.launch` | 系统诊断入口，不含 NDT 和地图服务器 |
| Gemini 336L | `roslaunch wheeltec_system_bringup wheeltec_orbbec336l.launch` | RGB、深度、点云、相机内部 TF 和安装 TF；不启动底盘 |

禁止同时启动 mapping 和 localization，禁止重复启动 Livox 或底盘节点。V4.0 仅保留 TEB 局部规划器，不提供 DWA 入口。

## 6. 话题

频率为当前配置下的期望值；实车验收以 `rostopic hz` 为准。“锁存”表示新订阅者连接后立即收到最后一帧。

### 6.1 雷达、FAST-LIO 与底盘

| 话题 | 类型 | 发布者 → 主要订阅者 | frame/频率/状态 | 用途 |
|---|---|---|---|---|
| `/livox/lidar` | `livox_ros_driver2/CustomMsg` | Livox → FAST-LIO | `livox_frame`，约 10 Hz | 原始 Livox 点云 |
| `/livox/imu` | `sensor_msgs/Imu` | Livox → FAST-LIO | 驱动时间戳，约 200 Hz | 雷达 IMU |
| `/Odometry` | `nav_msgs/Odometry` | FAST-LIO → mapper/诊断 | `camera_init`→`body`，约 10 Hz | FAST-LIO 原始位姿 |
| `/cloud_registered` | `sensor_msgs/PointCloud2` | FAST-LIO → mapper | `camera_init`，约 10 Hz | 世界系注册点云；建图输入 |
| `/cloud_registered_body` | `sensor_msgs/PointCloud2` | FAST-LIO → cloud adapter/原始local costmap | `body`，约10 Hz，随雷达前倾20° | 原始雷达体系注册点云；不能直接计算地面坡度 |
| `/cloud_registered_terrain` | `sensor_msgs/PointCloud2` | terrain cloud adapter → Patchwork++ | `terrain_sensor`，约10 Hz | 与雷达同原点、与base_link同姿态的水平地形点云 |
| `/path` | `nav_msgs/Path` | FAST-LIO → RViz/诊断 | 当前 `publish/path_en=false`，通常无消息 | FAST-LIO 轨迹；默认关闭 |
| `/cloud_effected` | `sensor_msgs/PointCloud2` | FAST-LIO | 发布调用在源码中关闭，通常无消息 | 有效特征点调试 |
| `/Laser_map` | `sensor_msgs/PointCloud2` | FAST-LIO | 发布调用在源码中关闭，通常无消息 | 局部激光地图调试 |
| `/odom` | `nav_msgs/Odometry` | 底盘 → move_base | header=`wheel_odom`，child=`base_footprint`，约 20 Hz | 编码器位姿与真实速度反馈 |
| `/imu` | `sensor_msgs/Imu` | 底盘 → 诊断 | `gyro_link`，约 20 Hz | 底盘板载 IMU |
| `/PowerVoltage` | `std_msgs/Float32` | 底盘 → 诊断 | 无 header，底盘周期 | 电池电压 |
| `/cmd_vel` | `geometry_msgs/Twist` | move_base/遥控 → 底盘 | 按控制周期 | 仅使用 `linear.x`、`angular.z` |

### 6.4 自适应地形分割

以下话题只在 `wheeltec_terrain_filter.launch`、Terrain建图或Terrain导航入口中存在。

| 话题 | 类型 | frame/频率/状态 | 用途 |
|---|---|---|---|
| `/terrain/patchwork_input` | `sensor_msgs/PointCloud2` | `terrain_sensor`，约10 Hz | Patchwork++ 处理后的完整输入调试副本 |
| `/terrain/patchwork_ground` | `sensor_msgs/PointCloud2` | `terrain_sensor`，约10 Hz | Patchwork++ 原始候选地面 |
| `/terrain/patchwork_nonground` | `sensor_msgs/PointCloud2` | `terrain_sensor`，约10 Hz | Patchwork++ 原始非地面 |
| `/terrain/ground_points` | `sensor_msgs/PointCloud2` | `terrain_sensor`，约10 Hz | terrain_guard 判定的安全候选地面；分类地图自由区输入 |
| `/terrain/unsafe_ground_points` | `sensor_msgs/PointCloud2` | `terrain_sensor`，约10 Hz | 坡度、台阶或粗糙度超限地面调试点 |
| `/terrain/obstacle_points` | `sensor_msgs/PointCloud2` | `terrain_sensor`，约10 Hz；标障点 z=0.20 m | local costmap marking 和分类地图障碍输入 |

| `/terrain/unknown_points` | `sensor_msgs/PointCloud2` | `terrain_sensor`，约10 Hz | 无可靠参考或不满足障碍高度规则的调试点 |
| `/terrain/status` | `diagnostic_msgs/DiagnosticArray` | 随处理帧 | 输入点数、分类点数、栅格数和处理耗时 |

同一输入帧的 ground、obstacle、clearing 和 status 时间戳一致。Terrain local costmap 不能把 `/terrain/obstacle_points` 同时用于 clearing。

## 13. 运行时清单核验

不同入口出现的话题不同，不能用一份 `rostopic list` 同时要求建图、定位、导航话题全部存在。按当前启动模式执行：

~~~bash
rosnode list | sort
rostopic list -v
rosservice list | sort
rosparam get /move_base  # 仅导航模式
rosrun tf view_frames
~~~

核对单个接口时使用：

~~~bash
rostopic info /TOPIC
rostopic type /TOPIC
rostopic hz /TOPIC
rostopic echo -n 1 /TOPIC
rosservice type /SERVICE
~~~

`rostopic list` 中存在但 `rostopic hz` 没有数据，不一定是故障：本表已标明 `/path`、`/cloud_effected`、`/Laser_map` 等默认关闭的调试输出，Orbbec 图像和点云还会按订阅者需求启流。反之，`/wheeltec/dynamic_points` 在当前配置下不会被创建。

## 14. 2026-09-01 rosbag 回归与当前边界

| 场景 | 使用时长/里程计帧 | 2.5D 已知格 | 致命格 | 轨迹连通性 |
|---|---:|---:|---:|---|
| 前方上楼梯 | 约37.8 s / 375 | 3610 | 1968 | 楼梯形成连续危险区域 |
| 前方下楼梯 | 约25.2 s / 249 | 1547 | 570 | 下落边缘形成连续危险区域 |
| 沿坡道下坡 | 约64 s / 647 | 13528 | 2968 | 647/647 轨迹点在同一可通行连通分量 |
| 沿坡道上坡 | 前65 s / 644 | 26218 | 8362 | 601/644 在主连通分量；异常尾段与原 bag 未正常关闭一致 |

第四个原 bag 未正常停止，只使用前65 s，不处理后面的重复路径。四包均完成原始点云处理、Patchwork++ 分割、分类累积、2.5D 六层生成和地图加载测试；测试期间未发布 `/cmd_vel`。TerrainGlobalPlanner 插件已在 NX 上加载，并通过 `/move_base/make_plan` 返回非空路径的静态测试。

当前边界：

- Patchwork++ 和 terrain_guard 保留，继续提供在线局部自适应地面、标障与 clearing；
- 每个 XY 栅格只保存一个地面高程，因此属于单层 2.5D，不表达桥上/桥下同一 XY 的多层拓扑；
- 坡度是软代价，连续台阶、粗糙地面和障碍是高代价或致命区域；TerrainGlobalPlanner 直接理解这些层，TEB 跟随其全局路径并处理动态障碍；
- 0.32 m 车体包络用于避免中心点可走但半个车身压上坡边或障碍的路径；
- rosbag 和静态 make_plan 结果不能替代有人持急停的低速实车验收。
