## 3. 坐标系与外参

车体约定为前 `+X`、左 `+Y`、上 `+Z`。

| TF | 类型 | 发布者 | 数值/说明 |
|---|---|---|---|

| `body -> base_link` | 静态 | `wheeltec_tf_manager` | 雷达前 0.10 m、上 0.15 m、车头方向下压 20 deg 的逆关系由配置发布 |

## 5. 正式数据流

### 5.1 建图

```text
/livox/lidar + /livox/imu
  -> FAST-LIO2
  -> /cloud_registered + /Odometry
  -> wheeltec_pointcloud_mapper（公共贝叶斯静态点判定）
     +-> filtered_camera_init.pcd
     +-> /wheeltec/static_scan (camera_init)
         -> cloud_adapter(terrain_sensor)
         -> Patchwork++ + terrain_guard
         -> ground/nonground 分类累积 PCD
         -> finalize_map.py
         -> map_raw/map PGM + public_map.pcd + terrain_2p5d 高程/坡度文件
```

正式建图中，完整 PCD、PGM 和 2.5D 地图共用 `/wheeltec/static_scan`；`/cloud_registered_body` 直连地形分割只作为诊断回退。导航实时避障仍使用原始实时点云，不经过建图静态滤波。

### 5.2 导航

```text
public_map.pcd + live cloud -> NDT -> map->odom
map_raw.yaml -> StaticLayer --------------------------+
terrain_2p5d cost -> TerrainCostmapLayer -------------+-> GlobalPlanner
live cloud - saved elevation -> obstacle/clearing ----+-> local costmap -> TEB -> /cmd_vel
```

导航阶段先保持 localization 运行，再叠加纯 navigation；不启动 Patchwork++/terrain_guard，保存的高程面直接作为实时点云的局部地面参考。

### 10.2 保存高程与坡度

| 参数 | 值 | 含义 |
|---|---:|---|
| `resolution` | 0.10 m | 高程栅格分辨率 |
| `ground_height_percentile` | 0.20 | 低分位地面高度 |
| `max_fill_radius_cells` | 4 | 小孔洞最大迭代填充范围 |
| `min_fill_neighbors` | 3 | 填洞最少邻格 |
| `fit_radius_m` | 0.30 m | 局部平面拟合半径 |
| `smooth_height_delta_m` | 0.12 m | 拟合邻点高度门限 |
| `preferred_slope_deg` | 5 deg | 不产生坡度成本的上限 |
| `max_slope_deg` | 25 deg | 持续超过时致命 |
| `max_slope_cost` | 80 | 非致命坡度最大软成本 |
| `min_lethal_neighbors` | 4 | 抑制孤立过陡噪点 |
| obstacle relative height | 0.08-1.50 m | nonground 融合进 2.5D 障碍的相对高度 |

分类点云累积体素为 `0.05 m`；障碍保存条件为至少 `3` 帧且观测跨度至少 `0.4 s`。粗糙度和台阶残差仍只供诊断，避免把稀疏点和插值边缘误判为致命障碍。

## 14. 已知边界

- 地形文件是单层 2.5D，每个 XY 只能保存一个地面高程，不支持桥上桥下等多层拓扑。
- 地图为离线静态结果，导航时不对全局高程做贝叶斯覆盖更新。
- 正式代价使用坡度和相对地面高度过滤后的分类障碍；粗糙度与坡面补偿高度残差只作诊断，不承诺完成楼梯语义识别。
- 实时障碍过滤依赖正确的 `map->terrain_sensor` TF 和当前地图的高程覆盖；定位错误会直接造成相对高度错误。
- 静态 PGM 不做预膨胀，global/local costmap 仅在运行时膨胀 `0.10 m`。TEB 始终按完整 footprint、`0.01 m` padding 和 `0.04 m` 净空做碰撞约束。
- 车宽 `0.40 m`、门宽 `0.60 m` 时，规划模型约占 `0.50 m`，理论剩余约 `0.05 m/侧`；地图误差、门框突出和斜着进门都会进一步消耗余量。
- 相机当前独立运行，不进入 Livox 建图、重定位或导航。

## 15. 故障矩阵

| 现象 | 检查顺序 |
|---|---|
| 全屋不可通行 | `/nav_static_map` -> 地图是否重新 finalize -> 坡度 cost 统计 -> 全局 costmap |
| 全屋像自由空间 | PGM 阈值 -> unknown 是否保持 -> TerrainCostmapLayer 是否错误覆盖未知 |
| 有路径但不走 | local costmap -> TEB local plan -> footprint -> 障碍距离 -> `/cmd_vel` 发布者 |
| 坡道被当障碍 | 地图名 -> `map->odom` -> 高程覆盖 -> `/cloud_registered_terrain` -> 相对高度话题 |
| 坡度没有影响全局路径 | terrain map server -> slope layer 参数 -> global costmap -> 路径是否存在替代路线 |
| 没有 map TF | `/initialpose` -> map PCD -> NDT 输入 -> global localizer 日志 |
| 没有地形话题 | `terrain_2p5d.yaml` 及六层文件 -> terrain map server 日志 |
| 底盘无反馈 | `lsusb` -> `/dev/ttyACM0` -> udev -> dialout -> `/odom` |
| 相机无图像 | USB ID -> 订阅者 -> Orbbec 服务/诊断 -> USB 带宽 |
