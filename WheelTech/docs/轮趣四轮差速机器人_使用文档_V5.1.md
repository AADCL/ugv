# 轮趣四轮差速机器人使用文档 V5.1 · BATF-Nav

> 技术名称：`BATF-NavBayesianAccumulationTerrainFusionNavigation`；简称 **BATF-Nav**；英文展开 **Bayesian Accumulation Terrain Fusion Navigation**。见[统一技术说明](https://github.com/AADCL/ugv/blob/main/docs/BATF-Nav_V5.1.md)。本次整理沿用 V5.1，按功能保留启动入口并接入探索。

> 更新：2026-09-11。以下命令以 `.123`（`nrc15`）为例，工作空间为 `~/livox_fastlio`；`.122` 使用 `nrc19`，本次未向 `.122` 部署。

> 本文只讲日常操作。安装、复制源码和开发验收见《开发实施文档 V5.1》；全部节点、话题和参数见《详细信息表 V5.1》。

## 1. 当前功能

日常只使用以下 6 个功能入口。保留原文件名；内部 `launch/include/*.launch.xml` 由它们调用，不需要另开终端启动。

| 功能 | 唯一操作命令 | 配合关系 |
|---|---|---|
| 相机 | `roslaunch wheeltec_system_bringup wheeltec_orbbec336l.launch` | 独立、可选 |
| 遥控建图 | `roslaunch wheeltec_system_bringup wheeltec_mapping.launch map_name:=factory_a` | 独立建图会话 |
| 重定位 | `roslaunch wheeltec_system_bringup wheeltec_localization.launch map_name:=factory_a` | 已有地图导航前先启动 |
| 导航 | `roslaunch wheeltec_navigation navigation_teb.launch map_name:=factory_a` | 叠加在已运行的重定位上 |
| 运行日志 | `roslaunch wheeltec_navigation nav_logging.launch tag:=factory_a` | 用于导航或探索，只记录 |
| 自主探索建图 | `roslaunch wheeltec_exploration wheeltec_exploration.launch map_name:=room_explore_01` | 就绪后自动探索，Ctrl+C 或完成后停车退出 |

地图最终生成继续使用原 `rosrun wheeltec_map_tools finalize_map.py NAME`，不另设 launch。供应商驱动示例不属于本表的项目功能入口。

NX 的 `~/livox_fastlio/launch/` 集中上述六个文件的快捷链接，源文件仍在各功能包中，原命令不变。不要手工复制第二份 launch 修改参数。根目录 `README.md` 提供工作空间索引；当前文档只看 `docs/`，地图与日志分别在 `maps/`、`logs/`。

数据流：

```text
建图：Livox + FAST-LIO2 + 贝叶斯静态 PCD -> PMF 种子 + 局部坡面生长 -> PGM/高程/坡度
导航：PCD/NDT 重定位 + PGM 占据 + 坡度软代价 + 当前帧局部地面分割 + TEB
```

PGM仍是全局占据/未知地图。高程文件只给全局路径增加坡度代价；局部障碍由当前帧地面分割产生，不查询保存高程。系统面向平地、整体斜坡和局部坡道组合；当前不承诺识别或通行楼梯。

## 2. 开机检查

登录并加载工作空间：

```bash
ssh nrc15@192.168.50.123
source ~/livox_fastlio/devel/setup.bash
```

检查 Livox 网络：

```bash
ip -4 addr show dev eth0
ping -c 2 192.168.1.165
```

检查底盘控制器：

```bash
lsusb
ls -l /dev/ttyACM0 /dev/wheeltec_controller
```

检查相机（需要相机时）：

```bash
lsusb | grep 2bc5:0807
```

开始操作前应满足：

- `eth0` 有 `192.168.1.5/24`；
- Mid-360 `192.168.1.165` 可达；
- `/dev/wheeltec_controller` 存在；
- 急停可用，车辆周围没有人员或易损物；
- 手动建图与已有地图定位/导航互斥；已有地图导航先定位、再叠加导航。
- 探索入口内部组合建图和导航，不额外启动建图、定位或导航；探索不运行 NDT。

## 4. 建图

### 4.1 启动

地图名只使用字母、数字和下划线，不要复用已有正式地图：

```bash
roslaunch wheeltec_system_bringup wheeltec_mapping.launch \
  map_name:=factory_a
```

这个入口默认只启动完整 PCD 建图，不再在线运行 Patchwork++ 或 ground/nonground 累积器。`wheeltec_pointcloud_mapper` 对 `/cloud_registered` 做半径滤波和可逆贝叶斯静态判定，保存的 `filtered_camera_init.pcd` 是唯一静态权威。最终转换直接从它生成 `public_map.pcd`，再用保守 PMF 种子和鲁棒局部平面恢复连续坡面，按相对高度重新提取障碍。需要排查旧分类链路时才设置 `enable_online_terrain_diagnostics:=true`；正式建图默认不启动 `terrain_guard`。

启动后，点至少命中 `12` 次、观测跨度达到 `2.0 s` 且命中率不低于 `60%` 才会晋升为静态点；此前静态点及分类话题为空或点数较少属于正常现象。正式建图不要覆盖默认输入。日常无需运行旧在线分类诊断；相关参数只在开发文档中说明。

### 4.2 确认数据

另开终端：

```bash
source ~/livox_fastlio/devel/setup.bash
rostopic hz /livox/lidar
rostopic hz /livox/imu
rostopic hz /Odometry
rostopic hz /cloud_registered
rostopic hz /wheeltec/static_scan
rostopic hz /wheeltec/static_map_cloud
```

注册点云通常约 10 Hz，静态整图默认每 2 s 发布一次。普通建图默认没有 Patchwork++ 相关话题；这些话题在导航、探索或显式诊断时才出现。检查 TF：

```bash
rosrun tf tf_echo camera_init body
rosrun tf tf_echo body base_link
rosrun tf tf_echo base_link terrain_sensor
```

### 4.3 采集路线

低速行驶并覆盖：

1. 起点周围和房间边界；
2. 可通行平地；
3. 坡底、坡中、坡顶；
4. 坡道两侧和回程方向；
5. 计划以后放置导航目标的区域。

高程地图只对实际观察到的地面可靠。单向快速经过坡道容易产生孔洞，应低速往返并让相邻扫描有重叠。

### 4.4 停止与自动保存

先让车辆完全停止，再在建图终端按一次 `Ctrl+C`，等待节点退出。贝叶斯静态 PCD 会周期保存并在正常退出时再保存，不需要手动调用 finish。

检查原始产物：

```bash
ls -lh ~/livox_fastlio/maps/factory_a
```

至少应有：

```text
filtered_camera_init.pcd
```

只有显式启用 `enable_online_terrain_diagnostics:=true` 时，目录中才会额外出现旧链路的两类 Patchwork++ 累积 PCD；默认转换不读取它们。

### 4.5 生成正式地图

```bash
source ~/livox_fastlio/devel/setup.bash
rosrun wheeltec_map_tools finalize_map.py factory_a
```

正常结束会打印 `[DONE] map finalized`。再次检查：

```bash
MAP_DIR=~/livox_fastlio/maps/factory_a
ls -lh "$MAP_DIR"
```

必须存在：

```text
public_map.pcd
map_raw.pgm
map_raw.yaml
map.pgm
map.yaml
terrain_ground_candidates_map.pcd
terrain_ground_map.pcd
terrain_obstacles_map.pcd
terrain_2p5d.yaml
terrain_2p5d_elevation.f32
terrain_2p5d_slope_deg.f32
terrain_2p5d_roughness.f32
terrain_2p5d_step_height.f32
terrain_2p5d_cost.u8
terrain_2p5d_confidence.u8
map_metadata.yaml
```

`map_raw.yaml` 是正式导航静态图；`map.yaml` 是不带离线障碍膨胀的兼容图。`terrain_ground_candidates_map.pcd` 是通过 PMF 与局部平面一致性确认的稀疏地面种子，`terrain_ground_map.pcd` 与 `terrain_obstacles_map.pcd` 是 PGM 和 2.5D 的正式输入。PGM 是静态障碍的唯一权威，2.5D 只叠加坡度；普通导航由 move_base 在运行时使用全局/局部 `0.15/0.22 m` 膨胀；探索单独覆盖为 `0.10/0.10 m`。不要删除任何 `terrain_2p5d_*` 文件，它们与 YAML 是一个整体。

如果目录中已有 `raw_camera_init.pcd`，转换工具会逐字节检查它是否与当前 `filtered_camera_init.pcd` 相同。不同则立即退出，防止把上一次建图的静态权威图与本次分类点云混合；只有明确替换整套地图时才使用 `--replace-raw`。

最终转换只读取最终贝叶斯静态 PCD，不再依赖历史 ground/nonground 标签。每个 `0.05 m` 格取低分位候选，大窗口 PMF 提供保守种子；候选必须有二维邻域支撑、局部平面残差合格，并沿不超过 `25°` 的连续坡面生长。最后只在原点云附近拟合地面，高于地面 `0.04-1.50 m` 的同源静态点成为障碍。只有在回归旧算法排障时才加 `--legacy-terrain-labels`，并在建图时启用在线地形诊断。

## 6. 正式导航

### 6.1 启动纯导航层

```bash
roslaunch wheeltec_navigation navigation_teb.launch \
  map_name:=factory_a
```

该命令必须在第5节的定位入口已经稳定运行后执行。它启动PGM、高程/坡度服务器、Patchwork++当前帧地面分割、Terrain Guard、GlobalPlanner、TEB和move_base，不会启动或替换Livox、FAST-LIO、NDT与底盘节点。定位与导航使用同一个 `map_name`。

两个终端的正确关系：

```text
终端1：wheeltec_localization.launch   # 持续运行，只启动一次
终端2：navigation_teb.launch          # 纯导航层
```

### 6.4 首次测试顺序

每次运动前告知现场人员并确认急停。目标按以下顺序逐步扩大：

1. 平地前方 0.5 m；
2. 平地前方 1.0 m；
3. 绕开单个固定障碍；
4. 坡底到坡中；
5. 坡中到坡顶；
6. 平地和坡道组合路线。

看到路径不等于可以放行。还要确认局部 costmap 未把坡面填满、TEB 有 local plan、`/cmd_vel` 连续且方向正确。

## 7. 自主探索建图

### 7.1 一键启动

先关闭之前的建图、重定位和导航会话，并告知现场人员小车即将自动探索。新地图使用新名字：

```bash
source ~/livox_fastlio/devel/setup.bash
roslaunch wheeltec_exploration wheeltec_exploration.launch map_name:=room_explore_01
```

此入口一次启动 Livox、FAST-LIO、原静态点云积累、实时局部感知、轻量探索记忆图、GlobalPlanner/TEB、探索底盘、安全门和前沿选择组件。在线不再调用整图转换，不生成 PGM 或 2.5D 文件。启动 launch 即表示开始本次探索：地图、TF、点云及导航状态就绪后，监督器自动申请安全门许可并开始选点，不需要另开终端调用服务。准备期间保持零速度。

### 7.2 自动就绪与开始

可选：另开终端观察，不是启动所必需的步骤：

```bash
source ~/livox_fastlio/devel/setup.bash
rostopic echo -n 1 /exploration/map_status
rosrun wheeltec_exploration check_exploration.py
rostopic echo -n 1 /wheeltec_safety/status
rostopic echo -n 1 /exploration/state
```

`ready:` 表示最新局部观测已写入探索记忆图；`WAITING_FOR_READY` 表示仍在等待启动条件。局部障碍层约 2 Hz 导出未膨胀观测，记忆图只保存未知、空闲和障碍，无需等待静态点晋升或完整转图。超过 2 s 没有有效记忆图更新，或前沿数据失效时进入 `PAUSED_WAITING_FOR_DATA`：停车、取消目标，保留点云积累；数据恢复稳定 2 s 且安全门仍健康并已获许可后继续。真实障碍或安全故障进入 `FAULT_STOPPED`，保持停车和诊断现场，不自动 reset 或 arm。

开发时如果只想观察而不运动，同一个入口追加 `auto_start:=false`，状态为 `WAITING_FOR_ARM`。这是可选诊断模式，日常自动探索无需此参数。

### 7.3 观察与日志

RViz Fixed Frame 为 `map`，使用第 6.3 节的地图和路径，另加：

| 类型 | 话题 | 含义 |
|---|---|---|
| Map | `/exploration/frontier_map` | 原全局 costmap 的前沿适配图，不是第二套建图算法 |
| Map | `/nav_static_map` | 本次探索的轻量观测记忆图，约 2 Hz；不是离线 PGM |
| Map | `/exploration/observed_local_map` | 局部障碍层未膨胀的真实观测，未知保持 -1 |
| Pose | `/explore/selected_goal` | 当前选择的真实边界目标 |
| MarkerArray | `/explore/frontiers` | 候选前沿 |

`/exploration/state` 为 `EXPLORING` 时有活跃目标；`WAITING_FOR_GOAL` 表示目标选择或等待阶段，不代表完成；`CONFIRMING_COMPLETE` 表示正在确认前沿已消失。连续 30 s 没有符合最小长度 0.50 m 的可达前沿、无活动目标、状态持续有效，并且期间至少有两次新的观测图更新成功，才报告 `COMPLETED` 并退出。地图缺失、TF 无效、规划失败或仍有前沿却暂时找不到路径，都不能当作完成。小房间可能在原地即可完成观测；墙外或小于阈值的零碎未知不代表一定需要驶入。新版轻量链路的完整房间实车自动结束仍待验收。

需要记录时仍使用原日志入口：

```bash
roslaunch wheeltec_navigation nav_logging.launch tag:=room_explore_01
```

它记录规划请求、安全门输出和探索状态。报告的 `command_topic` 指出本次统计的是普通 `/cmd_vel` 还是探索实际底盘 `/wheeltec_driver/cmd_vel`。

### 7.4 停止与保存

手动结束：在探索终端按一次 `Ctrl+C`，等待节点正常退出。自动结束：确认探索完成后，监督器先停车、停止目标选择、保存静态点云快照，再结束自身；它是 launch 的 required 节点，因此会带动本次探索其他节点正常退出。底盘和安全门继续保留退出归零/超时停车，原 mapper 保留正常退出保存。

两种结束方式之后都由你沿用原命令生成最终地图：

```bash
rosrun wheeltec_map_tools finalize_map.py room_explore_01
```

探索期间原静态 PCD 在内存积累，不周期存盘。正常退出后在 `~/livox_fastlio/maps/room_explore_01/` 保存 `filtered_camera_init.pcd` 和 `traversed_path_map.pcd`；再执行上面的命令，生成第 4.5 节的全部成果。新探索不创建 `.live/`，旧会话保留的 `.live/` 不能作为本次成果。需保留采集结果时应正常 Ctrl+C 收尾，不要直接断电。

需要额外远程停车时仍可执行 `rosservice call /wheeltec_safety/stop`，但它属于可选停止接口，不是日常启动步骤。锁停后 launch 保持运行，先检查 `/wheeltec_safety/status` 中的 `latched_reason`；需要结束时按 Ctrl+C，再运行原地图转换命令。现场排除原因后可重新启动探索，新采集建议使用新地图名。快照失败报告 `SAVE_FAILED`。独立日志终端需要另外按 Ctrl+C 结束。

探索目标选择已观测区域内能够容纳整车的位置；全局路径存在后还检查整车通行和近处局部障碍。车头与路径夹角较大时先对准路径，再由原 TEB 优化器控制前进。查看 `/move_base/TebLocalPlannerROS/execution_mode`：`ALIGN_TO_PATH` 为对准路径，`TEB_FORWARD` 为正常前进，`REPLAN_UNSUPPORTED_REVERSE` 或 `LOCAL_STOP_ENVELOPE_BLOCKED` 表示当前轨迹被拒绝并等待重规划。普通导航不使用此探索专用适配。

### 7.5 与普通导航的区别

探索只在专用覆盖文件中限速至 0.20 m/s、0.40 rad/s，禁止实际倒车，全局/局部膨胀均为 0.10 m。安全门使用完整车体轮廓、额外 0.02 m 余量及制动预测，不能用 0.10 m 膨胀理解安全停车距离。

普通导航原参数保留，导航 launch 不会启动重定位。探索用本次 FAST-LIO 建图定义 `map -> odom`，不叠加已有地图的 NDT。

探索的全局图仅用于记忆和连接目标，不做离线高程拟合或全局坡度代价优化；坡面的当前可通行性仍由原 Patchwork++ / Terrain Guard 和局部 costmap 处理。正式地图转换后，普通导航继续使用原 PGM 加坡度层。

## 8. 上位机 ROS 控制

NX 和上位机应处于同一 `192.168.50.0/24` 网段。假设上位机地址为 `192.168.50.X`：

NX：

```bash
export ROS_MASTER_URI=http://192.168.50.123:11311
export ROS_IP=192.168.50.123
```

上位机：

```bash

```

## 9. 普通导航停止顺序

1. 在 RViz 取消当前导航目标；
2. 发布一次零速度；
3. 停止导航日志并等待 bag 收尾；
4. 停止导航或定位 launch；
5. 确认 `/cmd_vel` 没有其他发布者；
6. 最后关闭底盘和传感器电源。

检查发布者：

```bash
rostopic info /cmd_vel
```

## 10. 快速排错

| 现象 | 处理 |
|---|---|
| `/dev/wheeltec_controller` 不存在 | 换回支持数据的 USB 线；检查 `lsusb`、`dmesg -w`、udev 和 dialout 组 |
| 启动导航后没有 `map` TF | 发布 `/initialpose`；检查 `public_map.pcd`、NDT 输入和 global localizer 日志 |
| 全屋都是不可通行 | 对比 `/nav_static_map` 与原 PGM；检查地图是否由当前版本重新 finalize；查看坡度层是否覆盖未知格 |
| 有全局路径但不走 | 查看 TEB local plan、局部 costmap、footprint、门洞实测净宽及车体是否对正 |
| 坡道进入局部图后全是障碍 | 检查Patchwork++地面比例、`sensor_height`、Terrain Guard坡度/台阶阈值 |
| 没有坡度/高程话题 | `terrain_2p5d.yaml` 或其二进制层缺失，重新执行 finalize |
| 目标在灰色未知区 | 重新采集覆盖该区域；不要开启 `allow_unknown` 绕过地图缺失 |
| 点云频率正常但定位跳动 | 检查初始位姿、PCD 坐标系、雷达外参和时间戳 |

## 11. 参数说明

- global/local costmap `inflation_radius=0.15/0.22 m`：全局优先保持窄门连通，局部保持实时安全包络。
- footprint：机器人真实几何轮廓，当前为 `0.50 m x 0.40 m`，padding为 `0.00 m`。
- TEB `min_obstacle_dist=0.04 m`：60 cm门洞模式下车体边缘希望保持的额外净空。
- TEB `inflation_dist=0.15 m`：轨迹优化的软代价距离，不是costmap膨胀半径。

40 cm 宽车体通过 60 cm 门洞只有约 10 cm/侧物理余量；考虑 padding、TEB 净空和地图误差后余量更小。进入门前应尽量正对门洞，低速通过。地图中的门洞净宽不足以容纳完整 footprint 和净空时，规划器拒绝通过是正确的碰撞保护。

四者含义不同。缩小 costmap 膨胀不会缩小真实车体，也不会让 TEB 无视碰撞。

### 11.1 起点安全逃逸

全局规划失败且车体可能处于静态误标障碍中时，`StartEscapeRecovery` 会执行门控检查。除局部 footprint 和后方走廊安全外，还必须有新鲜后向点云覆盖。当前Mid-360被车体遮挡，车后0.15～0.70 m近场实测为0点，因此自动倒退会被拒绝；必须接入后向传感器后才能实际启用。查看日志：

```bash
grep StartEscapeRecovery ~/.ros/log/latest/rosout.log
rosparam get /move_base/recovery_behaviors
```

## 12. 安全规则

- 未告知现场人员前，不发送 `/cmd_vel` 或导航目标。
- 首次测试不在坡边、台阶边缘、狭窄通道或人员附近进行。
- 重定位未稳定、TF 断裂、局部图大面积占据或 TEB 无局部路径时立即取消目标。
- 不同时运行两个底盘节点或两个 Livox 驱动；探索由自身入口组合建图与导航，其余入口按上述互斥关系使用。
- 导航测试必须是一个 localization 加一个 navigation，不能启动第二个 localization。
- 原始地图、PCD、rosbag 和日志不提交 GitHub。
